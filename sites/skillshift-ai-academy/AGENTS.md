# AGENTS.md

## 1. このファイルの役割

このファイルは、CodexがSkillShift AI AcademyのLPを制作・修正するときに必ず守る案件固有ルールです。

作業を始める前に、次の順序で資料を確認してください。

1. `AGENTS.md`
2. `README.md`
3. `inputs/SkillShift_AI_Academy_要件定義書.md`
4. `inputs/SkillShift_AI_Academy_LP原稿.md`
5. `inputs/SkillShift_AI_Academy_全体ワイヤーフレーム_v2.html`
6. `inputs/references/`内のFV・全体デザイン完成イメージ
7. `rules/`内のデザインルール一式
8. `assets/images/README.md`

資料同士で内容が食い違う場合は、以下の優先順位で判断してください。

1. ユーザーの最新指示
2. 要件定義書
3. LP原稿
4. 再構築ワイヤーフレーム
5. FV・全体デザイン完成イメージ
6. デザインルール
7. 競合参考サイト

競合サイトは、雰囲気・情報整理・視線誘導のみを参考にします。文章、構図、固有UI、画像をそのまま模倣しないでください。

## 2. プロジェクトの目的

- 対象：20〜40代の生成AI初心者の会社員
- 伝える価値：AIを学ぶだけで終わらせず、明日の仕事で使える力にする
- 最終目的：無料説明会への申込み
- メインCTA：`無料説明会に参加する`
- ブランド印象：信頼感、先進性、誠実さ、親しみやすさ
- 避ける印象：怪しい、安っぽい、子どもっぽい、過剰に派手なAI感

架空案件のため、未確認の実績、価格、講師経歴、受講者の声を事実として扱わないでください。仮データは画面上の注記とコードコメントで判別できるようにし、本番公開前の差し替え項目としてREADMEにも残してください。

## 3. 作業開始時のルール

1. 既存ファイルと技術構成を確認する。
2. ユーザーの既存変更を消さない。
3. 実装前に、今回変更する範囲と短い作業計画を示す。
4. 重大な矛盾や不足がなければ、確認待ちで止まらず作業を進める。
5. 既存の技術構成を尊重し、不要なフレームワーク移行や依存追加をしない。
6. 新規構築で技術指定がない場合は、静的HTML、CSS、JavaScriptを基本とする。

## 4. デザインルール

- FV完成イメージとFV以降の最終デザインイメージを、色・写真・空気感・情報階層の基準とする。
- ネイビー、ブルー、シアン、白を基本色とする。
- オレンジはCTAと重要箇所だけに限定する。
- 紫・ピンクの派手なAIグラデーションは使わない。
- 白背景と薄いブルー背景を機械的に交互配置しない。
- 全セクションを同じカードUIにしない。
- 1画面内の要素数を抑え、見出し・本文・写真・図解の優先順位を明確にする。
- 最終デザインイメージ以上に情報を詰め込まない。
- セクション間に十分な余白を設け、写真、横長図解、ロードマップ、比較、濃紺の帯を使い分ける。
- 装飾目的のアイコン、罫線、グロー、シャドウを増やしすぎない。
- アイコンは統一した線画SVGを使用し、絵文字は使わない。
- 実際の細則は`rules/`内の既存デザインルールを優先する。

### レイアウト目安

- コンテンツ最大幅：1120〜1200px
- 本文最大幅：680〜760px
- セクション上下余白：PC 96〜128px、スマホ 64〜88px
- 本文行間：1.7〜1.9
- カード間余白：PC 24〜32px、スマホ 16〜20px
- 角丸：小〜中程度。全要素を丸くしない
- シャドウ：薄く、必要な要素に限定
- 見出し：`clamp()`で画面幅に応じて調整

## 5. FV固有ルール

- 完成イメージ画像をFV全体の背景として貼らない。
- 人物写真、コピー、CTA、バッジ、浮遊UIを別々のHTML要素として実装する。
- PCは左にコピー、右に人物写真を配置する。
- スマホはコピーの可読性を優先し、人物の顔や手元を不自然に切らない。
- メインコピーは「AIを、学ぶだけで終わらせない。明日の仕事で使える力に。」を基本とする。
- 「未経験OK」「オンライン完結」「個別サポート」を簡潔に表示する。
- オレンジの主CTAを最も目立たせる。
- 「カリキュラムを見る」は補助リンクとして扱う。
- 浮遊UIはHTML/CSSで制作する。PCで最大4個、スマホでは最大2個を目安とする。
- FVの高さを固定しすぎず、小型ノートPCでもCTAを見切れさせない。

## 6. 画像・素材ルール

- 実装画像は`assets/images/`へ保存する。
- 使用予定のファイル名、比率、用途は`assets/images/README.md`に従う。
- 画像内に見出し、本文、ボタン、ロゴ、グラフ、UI文字を焼き込まない。
- UI画面、比較表、カリキュラム、料金表、FAQ、フォームはHTML/CSSで実装する。
- 写真が未完成の場合は同じ比率の仮領域を実装し、最終ファイル名を変えずに後から差し替えられるようにする。
- WebPまたはAVIFを優先し、表示サイズに対して過大な画像を配信しない。
- すべての`img`に適切な`alt`、`width`、`height`を設定する。
- FV以外の画像は原則`loading="lazy"`を設定する。
- 同一人物として見せる写真は、年齢・髪型・服装・雰囲気の連続性を保つ。

## 7. 実装ルール

- デザイントークンをCSS変数にまとめる。
- セマンティックHTMLを使用する。
- 360px幅でも横スクロールを発生させない。
- PC、タブレット、スマートフォンに対応する。
- CTAは最終申込フォームまたは設定済み予約URLへ遷移させる。
- CTAを各セクションへ機械的に置かない。主な配置はヘッダー、FV、中間、料金、最終申込エリアとする。
- スマホ下部固定CTAは、フォームとフッターに重ならないよう制御する。
- フォーカス表示、キーボード操作、色コントラストを確保する。
- アニメーションは控えめにし、`prefers-reduced-motion`に対応する。
- APIキーや認証情報をコードへ直書きしない。
- フォーム送信先が未設定の場合は、入力UIとバリデーションまで実装し、実送信を装わない。
- 架空LPであることをフッターに明記する。

## 8. 実装の進め方

品質を保つため、同じCodexチャット内で次の4回に分けます。

1. 共通基盤、ヘッダー、FV、悩み、Before／After、講座紹介、成果物、中間CTA
2. カリキュラム、学習方法、選ばれる理由、受講者事例、講師紹介
3. 料金、サポート、受講までの流れ、FAQ、説明会、フォーム、フッター
4. 全体QA、レスポンシブ調整、アクセシビリティ、表示速度、最終デザイン調整

完成済みの範囲を、次工程で不要に作り直さないでください。既存のCSS変数、コンポーネント、余白ルールを引き継いでください。

## 9. 検証ルール

変更後は、利用可能な範囲で次を実施してください。

- 開発サーバーまたはプレビューを起動する
- PC、768px前後、390px前後、360pxで表示を確認する
- 横スクロール、文字の重なり、画像の不自然な切れを確認する
- ヘッダー、アンカー、CTA、FAQ、フォームを操作する
- コンソールエラーを解消する
- ビルド、lint、テストがある場合は実行する
- 主要画面のアクセシビリティと表示速度を確認する

検証できなかった項目は、完了したように書かず、理由と手動確認方法を報告してください。
