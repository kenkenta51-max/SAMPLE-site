# LP専用 共通デザインルールブック v2.0

最終更新: 2026-08-06

> 再現するのは「見た目」ではなく「品質」。見た目は案件ごとに変える。

---

## 0. このルールブックの目的

本書は、業種・商品・サービス・ターゲットが異なるLPでも、一定以上の品質とコンバージョン導線を保ちながら、案件固有のブランド表現をつくるための共通基準である。

本書は「同じ見た目のLPを量産するテンプレート」ではない。

守るべきものは、情報の分かりやすさ、訴求との一致、視線誘導、信頼性、行動のしやすさ、可読性、アクセシビリティ、実装品質である。一方、配色、写真、余白、構図、タイポグラフィ、装飾、モーションなどの表現は、案件ごとに設計し直す。

### 適用範囲

- BtoC / BtoB
- 有形商品 / 無形サービス
- 店舗・予約型
- 通販・購入型
- 資料請求・問い合わせ型
- 高額商品・相談型
- セミナー・イベント申込み型
- 採用・応募型

---

# PART 1. 最重要原則

## 1-1. 品質は固定、表現は可変

本書のルールは、次の2層に分けて考える。

### A. 全案件で守る「品質ルール」

- 要件定義・訴求設計とデザインを一致させる
- 情報の優先順位を明確にする
- 1セクション1メッセージを基本とする
- 主CTAを明確にする
- 根拠・実績・条件を分かりやすく提示する
- 本文の可読性を確保する
- スマートフォンで情報順を再設計する
- アクセシビリティと操作性を確保する
- 実績・数値・口コミ・ロゴを捏造しない
- 表示速度を不必要な演出で損なわない

### B. 毎案件設計する「表現ルール」

- 配色
- フォント
- 写真・イラストの方向性
- 余白と密度
- コンテンツ幅
- セクションごとの構図
- 写真比率とトリミング
- 角丸・枠線・影
- 装飾モチーフ
- タイポグラフィ表現
- モーション
- 背景の扱い

表現ルールを全案件で固定しない。

## 1-2. 判断の優先順位

デザイン判断が競合した場合は、原則として次の順で優先する。

1. 法令・媒体審査・アクセシビリティなどの必須条件
2. クライアントの正式なブランドガイドライン
3. 要件定義・訴求設計・LP構成・承認済み原稿
4. 案件別 Brand Direction
5. 参考サイト分析から抽出したデザイン原則
6. 本書の共通品質ルール
7. 本書の未指定時Defaults
8. 一般的なWebデザイン慣習

重要なのは「案件をDefaultsへ合わせない」ことである。

案件固有の方向性を先に決め、決まっていない部分だけDefaultsで補う。

## 1-3. デザインの目的

LPのデザインは装飾ではない。訪問者が次を迷わず理解し、安心して行動できる状態をつくる。

1. 自分向けのページか
2. 何を提供しているか
3. どんな悩みを解決するか
4. どんな結果・体験を得られるか
5. なぜこの商品・サービスなのか
6. 信頼できる根拠は何か
7. 料金・条件・リスクは何か
8. 次に何をすればよいか

## 1-4. テンプレ感の判定基準

初稿・完成稿とも、必ず次を確認する。

> ロゴ、文章、写真を別案件のものへ差し替えても、そのまま成立するデザインになっていないか？

「はい」であれば、案件固有性が不足している可能性が高い。

# PART 2. デザイン開始前の Brand Direction

## 2-1. 必ず先に定義する

色や角丸を決める前に、次を案件別に定義する。

```md
## Brand Direction

デザインコンセプト：
このLPを一言で表すと：
ユーザーに感じてほしい感情：
優先する印象（3つ以内）：

主訴求を視覚的にどう表すか：
世界観：
写真表現：
タイポグラフィ：
余白・密度：
レイアウト：
色：
質感・装飾：
モーション：
スマートフォンでの見せ方：

この案件固有の表現：
1.
2.
3.

この案件では避ける表現：
1.
2.
3.

参考サイトから採用する原則：
1.
2.
3.

参考サイトから採用しない要素：
1.
2.
3.
```

最低でも「案件固有の表現」と「避ける表現」を3つずつ決める。

## 2-2. 参考サイトの使い方

参考サイトは表層をコピーしない。次のような「効いている理由」を抽出する。

- 情報の優先順位
- 写真と文字の主従
- 余白の取り方
- セクションのつなぎ方
- スケール差
- 視線の流れ
- 色の役割
- タイポグラフィの役割
- CTAの置き方
- ブランドらしさを生む反復要素

複数サイトの特徴を無計画に混ぜない。Brand Directionと矛盾する表現は採用しない。

# PART 3. 訴求・情報設計をデザインへ変換する

## 3-1. デザイン前に確認する5項目

| 項目 | 確認内容 |
|---|---|
| 最優先ターゲット | 誰に向けたLPか |
| 主訴求 | 最も伝える価値は何か |
| 信頼根拠 | 主訴求を何で証明するか |
| コンバージョン | 最終的に取ってほしい行動 |
| 主要な不安 | 行動を妨げる最大の理由 |

未確定のまま色・カード・装飾から決めない。

## 3-2. 情報の重要度

| 階層 | 対象 | 見せ方の考え方 |
|---|---|---|
| 最重要 | 主訴求、主要ベネフィット、主要CTA | 最大の視覚優先度 |
| 重要 | セクション見出し、実績、選ばれる理由 | 明確な階層差 |
| 補足 | 説明、条件、手順 | 読みやすさ優先 |
| 補助 | 注釈、タグ、出典 | 小さくしても判読性は保つ |

すべてを強調しない。重要度をサイズ、位置、余白、コントラスト、写真で表す。

## 3-3. 1セクション1メッセージ

各セクションは原則として1つの疑問に答える。

- 誰向けか
- 何が問題か
- どう解決するか
- 何が得られるか
- なぜ信頼できるか
- 他と何が違うか
- いくらかかるか
- どう始めるか

ただし「1セクション = 1つの四角い箱」という意味ではない。視覚上は隣接する場面と連続してよい。

# PART 4. ファーストビュー

## 4-1. 役割

3〜5秒を目安に、「自分に関係がある」「続きを見る価値がある」と判断できることを基本とする。

ただし、ホテル・美容・ファッション・高級商材など世界観が購買理由になる案件では、情報量を抑え第一印象と余韻を優先してよい。

## 4-2. 主な要素

- 最優先ターゲット
- 商品・サービスの内容
- 得られる結果または体験
- 競合と区別できる要素
- 必要に応じて主要CTA
- 信頼を補強する短い根拠
- ブランドを象徴するビジュアル

すべてを必ずFV内へ詰め込むという意味ではない。

## 4-3. 流入元との一致

広告、SNS、検索意図、営業資料などで約束した内容と主訴求を一致させる。流入元にない別訴求を最上位へ突然置かない。

## 4-4. FVの禁止事項

- 抽象コピーだけで内容が分からない
- H1を極端に大きくし、必要情報を追い出す
- CTAを複数同じ強さで置く
- 実績バッジを大量に並べる
- 無関係な海外人物・ストック写真を使う
- AI感の強い不自然な人物を使う
- 背景動画や3Dを理由なく使う
- 他案件のFV構図をそのまま転用する

# PART 5. レイアウトとスクロールリズム

## 5-1. セクションは「箱」ではなく「場面」

各セクションを「どのカード・箱に入れるか」から考えない。

まず、そこでユーザーに何を感じ、何を理解してほしいかを決め、それに合う構図を選ぶ。

## 5-2. ページ全体の緩急

次のような密度変化を意図的につくる。

`密 → 疎 → 大写真 → 短い言葉 → 情報密度高 → 証拠 → CTA`

最低でもページ全体で次のうち3種類以上の変化を検討する。

- 大 / 小
- 密 / 疎
- 明 / 暗
- 写真主体 / 文字主体
- 左 / 右 / 中央
- 静 / 動
- フル幅 / 狭幅
- 規則 / 非対称

変化そのものを目的にせず、Brand Directionの一貫性の中で行う。

## 5-3. コンテンツ幅のDefaults

- PC標準コンテナ: `1100〜1200px`
- 文章中心: `640〜760px`
- 情報量が多い表・比較: `1200〜1320px`程度を検討
- ワイド表現: `1280〜1440px` またはフル幅
- PC左右余白: `24〜64px`
- SP左右余白: `20〜24px`

これは固定値ではない。すべてのセクションを同じコンテナ幅へ収めない。

## 5-4. グリッド

- 12カラムは基準として使えるが固定しない
- 2カラムは `5:7 / 6:6 / 7:5` など内容で変える
- 3カラム均等は、本当に情報が同格の場合に限る
- 左右非対称、オフセット、余白側への寄せを許容する

「中央見出し + 均等3カード」を標準構図にしない。

## 5-5. セクション余白のDefaults

- PC: `80〜144px`
- SP: `56〜96px`
- 世界観や重要な間を見せる場面では、より広くてもよい
- 関連性が高い要素は狭く、意味が切り替わる箇所は広くする

全セクションへ同じ `padding-block` を機械的に適用しない。

## 5-6. セクション境界

毎回、背景色・罫線・大余白で明確に切らなくてよい。

写真、テキスト、余白、スケール、明暗、位置関係で場面転換をつくる。必要なら要素を視覚的に次セクションへつなげ、LP全体を一つのストーリーとして見せる。

# PART 6. 配色と背景

## 6-1. 色の役割

- Base / Background: ページの基調
- Main / Primary: ブランドの中心色
- Accent / CTA: 行動や限定的な強調
- Text: 主要文字・補助文字
- Border / State: 必要時のみ

色数を増やすより、写真、余白、文字、濃淡、素材感で表情をつくる。

## 6-2. 背景色は区切り記号にしない

次のような機械的な交互背景を標準にしない。

`白 → 薄いベージュ → 白 → 薄いベージュ → 白`

背景を変える場合は、最低でも次のどれかの理由を説明できるようにする。

- 意味の章が切り替わる
- 感情のトーンが変わる
- 重要情報を強調する
- ブランド世界観を転換する
- CTAやオファーを明確に区別する

## 6-3. 色数のDefaults

- Base: 1〜2色
- Main: 1色
- Accent: 1色
- Text: 1〜2色

`70 / 20 / 10` のような比率は参考値であり、全案件へ固定適用しない。

## 6-4. CTAカラー

CTA専用色を採用する場合は、見出し、マーカー、アイコンなどへ無計画に流用しない。ただしブランド上、CTAが主色と同色でも十分な識別性があれば問題ない。

## 6-5. コントラスト

- 通常文字: 原則 `4.5:1` 以上
- 大きな文字: 原則 `3:1` 以上
- 色だけで状態や意味を伝えない
- 薄い背景に薄い小文字を置かない

## 6-6. 純白・純黒

高級、自然、温かさ、静けさが重要な案件では `#FFFFFF / #000000` を自動採用しない。オフホワイトやチャコール、有彩色寄りニュートラルも検討する。

# PART 7. タイポグラフィ

## 7-1. 文字サイズのDefaults

| 用途 | PC目安 | SP目安 |
|---|---:|---:|
| Hero / Display | 56〜88px | 38〜56px |
| H1 | 48〜72px | 36〜48px |
| H2 | 36〜48px | 28〜36px |
| H3 | 24〜32px | 22〜28px |
| Lead | 18〜24px | 17〜21px |
| Body | 16〜18px | 15〜17px |
| Caption / Label | 12〜14px | 12〜14px |

必要に応じて `clamp()` を使用する。数値レンジの中央値を毎回採用しない。

## 7-2. 行間と行長

- 見出し: `1.1〜1.35`
- 本文: `1.65〜2.0`
- 日本語本文: 1行 `28〜40文字` 程度を目安
- 長文を画面幅いっぱいへ広げない

## 7-3. 改行

- 意味のまとまりで改行する
- 助詞や読点直後など不自然な改行を避ける
- PC専用改行がSPで破綻しないよう調整する
- 1文字だけ次行へ残る状態を避ける

## 7-4. 文字をグラフィックとして使う

ブランドに合う場合、文字を画面構成要素として使ってよい。

- 大きなブランドコピー
- セクションナンバー
- 縦組み
- 左右へ寄せた見出し
- 写真への重なり
- 大きな余白の中の短い一文

意味の薄い英語を装飾目的だけで追加しない。

# PART 8. 写真・画像・図解

## 8-1. 画像には役割を持たせる

- 商品の形・品質・質感を見せる
- 利用場面を見せる
- 利用後の状態や体験を想像させる
- 人や会社の信頼を高める
- 実績・変化を証明する
- 仕組みを分かりやすくする
- 感情を動かす
- ブランドの空気感を伝える

役割を説明できない画像は削除する。

## 8-2. 写真を「枠の中の素材」に限定しない

必要に応じて写真をレイアウトそのものとして使う。

- 画面端まで広げる
- フルブリードにする
- 縦長・横長を使い分ける
- 大小の写真を組み合わせる
- 写真同士をずらす
- テキストを写真へ重ねる
- セクション境界をまたがせる
- 被写体に合わせて大胆にトリミングする

すべてを同じ幅、同じ比率、同じ角丸へ揃えない。

同じ役割の連続画像は統一感を持たせつつ、ページ全体では写真のスケールや比率に意図的な変化をつけてよい。

## 8-3. 写真ディレクション

案件内で次の方向性を揃える。

- 光
- 色温度
- 彩度
- コントラスト
- 被写体との距離
- 人物の雰囲気
- 背景
- 質感
- トリミング方針

## 8-4. AI生成画像

- 人体、指、文字、ロゴ、商品形状の破綻を確認する
- 実在商品・実績をAI画像で代用しない
- 実在しない人物を顧客・社員・専門家として見せない
- ブランドに合う光・色・質感へ揃える
- 素材不足を理由に、事実性が必要な写真を捏造しない

## 8-5. 図解

文章だけでは理解しにくい関係がある場合に使う。

- 手順
- 比較
- 仕組み
- 導入前後
- 費用対効果
- 数値の関係

一文で理解できる内容を装飾目的だけで図解しない。

# PART 9. カード・ボックス・角丸・影

## 9-1. カードは標準UIではない

次を満たす場合に使う。

- 情報が独立した単位である
- 比較・選択・一覧性を高める必要がある
- カード化した方が理解が速い

単に「整って見える」ことを理由にカード化しない。

特に美容、ホテル、ファッション、高級商材など世界観重視のLPでは、カードの使用量を抑え、写真・余白・タイポグラフィ・編集的レイアウトを優先して検討する。

## 9-2. 角丸のDefaults

- 小: `4〜8px`
- 中: `12〜16px`
- 大: `20〜24px`
- ピル型: CTA・タグなど用途が明確な場合

案件全体で角丸を揃えること自体を目的にしない。ブランドがシャープなら `0〜4px` も選択肢とする。

## 9-3. 影

- 階層差・浮遊を示す理由がある場合だけ使う
- 「カードらしくするため」の薄い影を乱用しない
- 高級・ミニマル系では、余白・線・面・写真のコントラストを優先する

## 9-4. 境界線

- 基本は `1px` 程度を起点とする
- 強い囲みより淡い線や余白でグルーピングする
- 全要素をボックスで囲わない

# PART 10. CTAと行動導線

## 10-1. コンバージョン

主要コンバージョンは原則1つに絞る。補助CTAを設ける場合も、主要CTAより弱く見せる。

## 10-2. CTAの配置

候補:

- ファーストビュー
- ベネフィット理解後
- 実績・事例確認後
- 料金・オファー確認後
- FAQ後
- ページ最下部
- SP固定CTA

全セクション後へ機械的に置かない。ユーザーが「行動してもよい」と感じる節目へ置く。

## 10-3. CTA直前の判断材料

段階に応じて、得られる結果、費用、条件、実績、保証、対応範囲、所要時間、申込み後の流れ、不安解消を配置する。

## 10-4. ボタンDefaults

- 高さ: PC `48〜60px`、SP `48〜56px`
- 横padding: `24〜36px`
- タップ領域: 最低 `44×44px`
- 文言は行動結果が分かる表現にする

「詳しくはこちら」だけに頼らない。

## 10-5. 固定CTA

LPが長い、予約・電話・問い合わせが主目的など、いつでも行動できる利便性が重要な場合に検討する。画面を圧迫したり本文・Cookie表示へ重ねたりしない。

---

# PART 11. 信頼・実績・比較・料金

## 11-1. 信頼材料

- 導入件数・顧客数・継続率
- 創業年数
- 資格・認証・受賞歴
- 取引先ロゴ
- 顧客の声・導入事例
- 担当者・専門家
- 所在地
- 料金
- 提供の流れ
- 保証・サポート

案件に必要なものだけ使う。

## 11-2. 実績

- 数字は単位・期間・対象を明示する
- 出典や算定条件を注記する
- ロゴの掲載許可を確認する
- 顧客の声は属性・条件を可能な範囲で示す
- 個人差がある結果には適切に注記する

## 11-3. 比較

- 比較軸を先に定義する
- 自社に都合のよい項目だけを選ばない
- 他社を根拠なく否定しない
- 重要な差を視覚的に強調する
- SPで読める構成へ再設計する

## 11-4. 料金・オファー

必要に応じて、価格、税込/税別、含まれる内容、追加料金、契約・解約条件、送料・地域、特典、期限、保証、申込方法を明示する。

## 11-5. 禁止

- 根拠のないNo.1
- 架空の数字・口コミ・ロゴ
- 実績のない二重価格
- 偽の残り時間・残数
- 重要条件を極端に小さくする
- 根拠なく効果を断定する

---

# PART 12. フォーム

## 12-1. 入力項目

そのコンバージョン段階で必要な項目だけに絞る。「営業上あると便利」な項目を初回フォームへ増やしすぎない。

## 12-2. 表示と入力

- プレースホルダーだけで項目名を示さない
- 必須・任意を明示する
- 必要に応じて入力例を示す
- SPのキーボード種別を項目に合わせる
- 長いフォームでは段階分けも検討する

## 12-3. エラー・完了

- 何をどう直せばよいか具体的に示す
- 他の入力済み項目を消さない
- 送信後は完了、返信目安、次の行動を示す
- CTA文言とフォーム内容を一致させる

---

# PART 13. スマートフォン

## 13-1. PCの縮小版にしない

SPでは情報の順番と見せ方を再設計する。

- 見出し改行をSP用に調整する
- 写真トリミングをSP用に調整する
- PCの左右非対称を上下のリズムへ置き換える
- 必要なら画像と文章の順番を変える
- 比較表は横スクロール、要点比較、カード等から最適方式を選ぶ
- CTA到達性を確認する
- 世界観に必要な余白は残しつつ、間延びは防ぐ
- 重なり表現を再配置する
- 横スクロールを発生させない

## 13-2. SP確認

- [ ] 対象・価値・次の行動が理解できる
- [ ] 見出しが大きすぎない
- [ ] 不自然な改行がない
- [ ] 画像の重要部分が切れていない
- [ ] 固定要素が本文を隠さない
- [ ] 表・料金・比較が読める
- [ ] ボタン・フォームが操作しやすい
- [ ] PCで作った世界観がSPでも失われていない

---

# PART 14. モーション

モーションは豪華さを足すためではなく、視線誘導、状態変化、理解、世界観の補助に使う。

- 控えめな fade / translate / clip reveal を起点に検討
- duration目安: `300〜800ms`
- 自然な減速を基本とする
- 全要素を順番に出現させない
- 読む前に本文を隠し続けない
- スクロールを乗っ取らない
- 過剰な3D・カーソル追従・パララックスを避ける
- 重いライブラリを演出だけのために導入しない
- `prefers-reduced-motion` に対応する

静けさがブランド価値なら「動かさない」ことも積極的なデザイン判断とする。

---

# PART 15. アクセシビリティ・SEO・表示速度

## 15-1. アクセシビリティ

- 適切なコントラストを確保する
- 小さすぎる文字を避ける
- キーボード操作を可能にする
- フォーカス状態を表示する
- 適切なaltを付ける
- 見出し階層を正しく使う
- ボタンとリンクを使い分ける
- 色だけで状態を伝えない
- フォームへラベルを付ける
- reduced motionへ対応する

## 15-2. HTML構造

- H1は原則1ページ1つ
- H2は主要セクション
- H3はH2の下位項目
- `header / nav / main / section / article / aside / footer` を意味に応じて使う
- 見た目のためだけに見出し階層を変更しない

## 15-3. 基本設定

必要に応じて `title / meta description / OGP / canonical / favicon / robots / sitemap / alt / 構造化データ / コンバージョン計測` を設定する。

## 15-4. 表示速度

- WebP / AVIF等、適切な形式を使う
- 表示サイズへ画像を最適化する
- width / heightを指定する
- FV画像の読み込み優先度を調整する
- 画面外画像を遅延読み込みする
- 不要なJavaScriptを減らす
- 不要なフォントウェイトを読み込まない
- 大型ライブラリを無計画に導入しない
- CSSを重複させない

---

# PART 16. 脱テンプレの具体ルール

## 16-1. 標準構図として使わないもの

次を「無難だから」という理由で採用しない。

- 白 → 薄色 → 白 → 薄色の交互背景
- `見出し → 説明 → 3カード` の反復
- 全要素のカード化
- 全画像を同一比率・同一角丸にする
- `画像｜文章 → 文章｜画像` の左右交互だけで構成する
- 中央揃え見出しの連続
- 全セクション同一余白
- 毎回 `英字ラベル + 日本語見出し + 本文` の型
- すべてのセクションを同一コンテナへ収める
- SaaS風の紫青グラデーション、光彩、3Dを無条件に使う

## 16-2. 禁止ではなく「理由が必要」

上記の表現自体を全面禁止するわけではない。内容とBrand Directionに合い、採用理由を説明できる場合は使用できる。

例: 3つのプランを同条件で比較するなら均等3カードは合理的である。

## 16-3. セクションごとの構図決定

各セクションを作る前に、最低限次を判断する。

1. この場面で伝える1メッセージは何か
2. ユーザーに何を感じてほしいか
3. 証拠・写真・数値のうち何が主役か
4. 前後セクションとどうリズムを変えるか
5. Brand Directionのどの表現をここで使うか

この5点から構図を決める。

# PART 17. AI生成LPで特に避ける表現

- 全要素のカード化
- 大きすぎる角丸
- 強いドロップシャドウ
- 意味のない光彩・ネオン
- 絵文字をアイコン代用
- 中央揃えだらけの文章
- 無関係な海外人物
- ブランドと無関係な3Dオブジェクト
- 意味の薄い英語ラベル
- 小さい文字だけで高級感を演出
- 背景装飾を埋め尽くす
- 全セクション同じfade-in
- CTAをすべてのセクション後へ置く
- 仮素材・仮文言を説明なく確定扱いする
- 参考サイトの表層コピー

# PART 18. 品質評価 v2.0

各項目を10点満点で評価する。

| # | 評価項目 | 確認内容 | 点数 |
|---:|---|---|---:|
| 1 | 訴求の明確さ | 誰向け・何・結果が分かる | /10 |
| 2 | 情報の優先順位 | 重要度が見た目で分かる | /10 |
| 3 | 説得の流れ | 疑問・不安に自然な順番で答える | /10 |
| 4 | ブランド固有性 | 他案件への差し替えで成立しない固有性がある | /10 |
| 5 | 視覚リズム | 構図・密度・スケールに意味のある緩急がある | /10 |
| 6 | 配色・タイポグラフィ | 世界観と可読性を両立する | /10 |
| 7 | 写真・ビジュアル | 役割・品質・ブランド整合性がある | /10 |
| 8 | CTA・信頼・フォーム | 根拠が伝わり行動しやすい | /10 |
| 9 | スマートフォン | 情報順・世界観・操作性が最適化されている | /10 |
| 10 | 技術品質 | 速度・SEO・アクセシビリティ・安定性 | /10 |
|  | 合計 |  | **/100** |

### 合格基準

- 90〜100点: 公開・納品候補
- 80〜89点: 軽微な修正後に公開可能

- 59点以下: 要件・訴求設計から再確認

原則、合計80点以上かつ各項目6点以上を公開候補とする。

ただしAIの自己採点だけで合格としない。実画面・実機を確認し、最終判断は人が行う。

# PART 23. 最終原則

本書の目的は、全LPを同じ見た目へ揃えることではない。

良いLPは、共通の品質基準を満たしていても、案件ごとに表情が違う。

同じなのは、分かりやすさ、説得力、信頼性、使いやすさ、丁寧な実装である。

違うべきなのは、写真、余白、構図、色、文字、リズム、空気感、そしてブランドの記憶である。

**再現するのは品質。ブランドの個性は毎回つくり直す。**
